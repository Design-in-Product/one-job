## 2026-08-31 — brief applied, and it caught a real defect in two-day-old code

Brief: **"a widening turns a previously-unreachable narrow filter into a
live silent default"** (Klatch round124) — when an outer set grows, inner
filters anchored to the old population silently misclassify new members,
and the check count RISES while coverage shrinks.

Ran the discriminating probe the brief prescribes against my own freshest
anchored-filter code — `scripts/fleet-probe.mjs` (written 08-29). Fed it
three headings the outer regex accepts but the inner filters can't
classify. **All three misfiled, exit 0:**
- `✔︎ 91.` and `CLOSED 92.` (closed, marked differently) → **dealt to Xian
  as live work**. The closed-filter was `!heading.startsWith('✅')`.
- `90. URGENT` (no marker) → **silently ranked into the 🟢 bucket**,
  buried under the FYI cards. `rank()` ended in a bare `: 2`.
- Card count rose 10→13, reading as increased coverage. Textbook.

Fixed by making classification exhaustive (open/closed/unclassified) and
refusing to write a deck when anything is unclassified — Xian's own
deterministic-pipeline principle (08-24: surface the unhandled shape,
never absorb it), rather than widening the anchors, which would just be
whack-a-mole. **Verified both directions** per the 08-30 brief: red on
the probe fixture (naming each bad heading), green on the real rollup
with the identical 10 cards. 6 regression tests assert every verdict the
classifier can return, including the two that used to misfile. 189/189.
Commit 7e07e7e.

Worth noting the compounding: 08-30's brief (checks must be able to go
