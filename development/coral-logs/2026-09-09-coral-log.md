## The watchdog shipped in the propagation window (rc.39)

Themis's on-ramp caution made the PWA fix urgent; Apple's propagation
delay made it free. Built, tested, and verified in the gap:

- **Inline in index.html** — in the failure state the bundle is exactly
  what never loaded, so the HTML is the only place recovery can live.
- **Controller gate** (improvement over the plan): arms only when a SW
  controls the page — the only state the failure can exist in — so a
  slow first visit is structurally exempt from false positives, not
  just unlikely to hit one.
- **The hard rule is an assertion**: unit tests run the exact bytes
  extracted from index.html (no parallel testable copy to drift) and
  prove the heal never touches localStorage. The give-up copy warns
  *against* clearing site data, because that advice would delete decks.
- **Deliberate reproduction** (Playwright, real build): manufactured
  the exact broken state — cached HTML, evicted cache entry, missing
  server asset. Watchdog healed; deck survived byte-for-byte; broken
  window bounded at 2 navigations; healthy controlled boot sat 10s past
  the timer untouched; recovery after "deploy completes" booted clean.

**The e2e caught two real defects the unit suite couldn't:**
1. My own probe called the give-up screen "RECOVERED" — children.length
   matches the honest-stop message too. m-52 in miniature: I read a
   proxy (non-empty root), not the property (the app mounted). Fixed
   with an id on the fallback and a mounted-means-no-fallback check.
2. The boot hook was defined inside the controller gate, so the
   UNcontrolled clean boot that follows every heal never cleared the
   attempt counter — a stale count silently shrinking the next
   failure's budget. Moved the hook outside the gate.

Both are the week's briefs applying to my own verification: the test
that proves the mechanism is not the test that proves the outcome.

Also from the diagnostics: vite preview's SPA fallback serves HTML as
JS with a 200, which can poison a workbox precache — a preview-server
artifact, impossible on Pages (real 404s, which workbox refuses to
cache). Noted so nobody chases it as a production bug.
