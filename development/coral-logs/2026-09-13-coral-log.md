# Coral Log: 2026-09-13

## Brief applied: the content-presence gate on import

Klatch's round-197 finding (SQLite passes a 0-byte file as a valid
empty database) audited straight into our most protected surface:
stageImport validated FORMAT only, and importTasks full-replaces — so
a well-formed-but-empty backup, the exact artifact an interrupted
export produces, would have wiped a full deck while passing every
check. The 07-05 disaster's shape, one costume later, sitting in the
restore path since v3 shipped.

Gate added at the store: zero incoming cards + anything to lose =
refusal, with a message that names the likely cause ("if the export
that made it reported success, that export failed silently"). Empty-
over-empty proceeds (fresh devices restore fine). Four RED-zone tests
seen failing first.

Two process notes, both mine:
1. A pre-existing snapshot-guard test used importTasks([]) as its
   VEHICLE — the gate refused it and the test went red. Right fix was
   a legitimate empty route (trash+purge), keeping BOTH defense lines
   independently tested. Layered defenses must not share test
   vehicles, or removing one silently untests the other.
2. `vitest | grep "Tests "` swallowed the exit code and I pushed a red
   suite for ~3 minutes before the fix followed. CI's beacon would
   have caught it, but the grep habit is the defect: piping a gate
   through a filter discards the gate. Noted for my own command
   hygiene: run the gate bare, filter afterwards.
