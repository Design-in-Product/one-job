
## The brief's three defaults, audited — two live, and I demonstrated the third on myself

**Insight 2 (vacuous green) — real, found in v1-fixtures.** Every
assertion about interiors lived INSIDE `for (const deck of task.decks
?? [])`. A migration that stopped producing interiors would have made
the loop body unreachable and the whole suite green while verifying
nothing. Fixed with corpus-level counters asserted in afterAll.
**My first version asserted per-fixture and was wrong** — four fixtures
legitimately have no interiors — and the new guard caught my false
assumption on its first run, which is the best possible introduction.
Mutation-verified: emptying the loop turns it red.

**Insight 3 (stale clone + git add -A) — live risk, now a hook.** My
`git add -A` habit plus this repo's concurrent committers (Janus's
briefs, Themis's mail) is precisely the configuration that cost Pard
1,683 files. `.githooks/pre-commit` refuses a commit that stages
deletions while the clone is behind origin, fetching only when
deletions exist so normal commits stay fast.

**And then I did the adjacent version of it to myself.** Testing the
hook, I ran `rm <file> && git add -A && git commit` to see it refuse.
The clone was current, so the hook correctly allowed it — and
`git add -A` swept the deletion into a real commit titled "should be
refused if behind," taking `docs/releases/1.1-38.md` with it. Caught it
in the same breath (the follow-up commit reported "nothing to commit,"
which was the tell), restored from HEAD~1 and amended before anything
was pushed.

The lesson is not the hook's; it is the brief's actual point, which I
had just finished writing code about: **`git add -A` stages whatever
the working tree says, including things you did on purpose for a
different reason.** A synthetic deletion is still a deletion. Testing
a destructive-path guard by performing the destructive act is the
wrong experiment — the right one asserts on the hook's logic without
touching real files.
