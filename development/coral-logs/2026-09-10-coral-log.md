## The 9-day freeze gets its structural answer (09-10 brief applied)

The brief's theme — CI enforcement, silence-shaped holes — arrived the
morning after I found ours. Shipped four layers, chokepoint-attached
where possible (m-53):

1. **ci-red-beacon job in deploy.yml**: any job failure files/updates a
   "CI red" GitHub issue from inside the workflow itself. Root cause of
   the freeze's invisibility: failure emails go to commit authors, and
   this repo's author is an agent identity with no inbox. The beacon
   moves failure into channels that ARE read (gh, session-start sweep,
   Xian's GH notifications). needs ALL four jobs — a beacon watching
   only test+build would be silent on deploy/verify failures, the same
   hole reborn.
2. **Session-start CI check** added to CLAUDE.md's mandatory checklist
   — five seconds, and the beacon could itself break.
3. **Persistent session monitor** on deploy.yml conclusions (red +
   recovery events).
4. **Key-literal drift test**: metricsStore reads 'oneJobTasks' but
   can't import taskStore (cycle) — PM's read-the-source pattern in
   minimum form pins the two literals together; drift now fails the
   build instead of silently degrading cold-start provenance.

Also insight 1 found a real instance here: compose-store-shots treated
a misspelled PROFILE as a STAGING DIR — 'iphone67' composed zero shots
at exit 0. Now: two refusals plus a "Composing: N of M profiles" scope
line (the filter-took signal that survives every spelling).

Deploy green post-hardening; CI history is being watched from three
directions it wasn't yesterday.
