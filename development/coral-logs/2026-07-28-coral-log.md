### Bringing the project up on a new machine — three traps, all found
`node_modules` was absent; everything below came out of that first
`npm install`.

**1. npm 11.17 blocks install scripts by default.** The install
"succeeded" and printed a warning in its tail, but produced a tree with
no esbuild binary and no @swc native binding — vite could not have
built. Textbook m-44: the success signal didn't name what it skipped.
Fixed by `npm approve-scripts esbuild @swc/core fsevents`, and the
approvals are now recorded in package.json so Relay's fresh clone
doesn't rediscover it. (Commit b6d75b5.)

**2. The 88-green suite came up 63 RED — and it was the host, not us.**
`localStorage is undefined`. Root cause, probed rather than guessed
(a throwaway test printing the environment globals): jsdom no longer
ships its own localStorage, it defers to the platform's; **Node 26 has
a built-in localStorage that is inert without `--localstorage-file`**,
so `window.localStorage` is undefined. Node 22 — the old remote
container, and what CI still pins — has no built-in, so jsdom's
implementation shone through and the same commit was genuinely green
there. Both readings were true; the environment moved.
Fix: `src/test/setup.ts` installs a deterministic in-memory Storage
unconditionally and clears it between tests, so the suite no longer
depends on the host's Node. 88/88 green. (Commit dda4310.)

**3. Lockfile churn had to be read before it was committed.** npm's
dedupe dropped 514 lines. Verified before staging: the removals are
vitest's nested esbuild + its 26 platform binaries, and vitest 4.1.9
doesn't depend on esbuild at all (checked manifest and resolution).
vite's own esbuild tree still carries linux-x64, which is what ubuntu
CI's `npm ci` needs for the Pages build. Safe.

  was honestly green on Node 22 and honestly red on Node 26, with no
  code change between. The fix wasn't to pin the environment but to
  remove the dependence on it. Generalizes: when a test needs a
