## PAT tested — new finding: a sandbox-level git-credential proxy blocks it

Xian pasted a fine-grained PAT mid-session. Tested two ways: an
`api.github.com` call with the token in the Authorization header (same
canned "add_repo" 403 seen earlier with no credential at all), and a
`git push --dry-run` with the token embedded in the URL (no real write).
Both were denied by what identifies itself as **"the git proxy"** —
`Design-in-Product/one-job is not in this session's authorized repository
set, so the proxy will not inject a credential for it.`

Conclusion: not a token-scope problem. The sandbox routes all
authenticated GitHub traffic through a proxy that ignores externally
supplied credentials and only injects its own for repos on a per-session
authorized list. `one-job` isn't on it. No PAT, however scoped, works here
as currently configured. Full write-up filed fresh the next session (see
2026-08-08 log) rather than rushed same-day.
