## Decision: `project.pbxproj` should NOT be gitignored — the opposite

Xian asked whether to gitignore it, reasonably, since its reverting is what
re-armed the BUNDLEID trap on 07-31.

**No.** `project.pbxproj` *is* the Xcode project — targets, build phases,
settings, file references. Ignoring it would mean a fresh clone has no
buildable iOS project at all. (What *is* conventionally ignored is
`xcuserdata/`, which holds per-user window and scheme state — already covered.)

The actual fix is the inverse: **commit the two lines that keep getting lost**,
so they persist across checkouts and every future tag carries them.

```
DEVELOPMENT_TEAM = YZ4B34YGX9      (was absent → Team came up "None")
CURRENT_PROJECT_VERSION = 2        (was 1)
```

Committing `DEVELOPMENT_TEAM` disarms the trap permanently: a fresh checkout of
any future tag arrives with the paid team already selected, so there is no
moment where the free Personal Team sits one row away in a dropdown waiting to
burn another bundle id.

Note for the record: a Team ID is **not a secret** — it ships inside every
distributed app binary and appears in provisioning profiles. Committing it to a
public repo exposes nothing that isn't already public. (Distinct from the
`.p8` App Store Connect key in `docs/AMBER-XCODE.md`, which *is* a secret and
must stay outside the repo.)

`CURRENT_PROJECT_VERSION = 2` also gets committed so the next cut starts from a
known number rather than from whatever the last checkout happened to leave.
