## Ordering decision made this session

The brief says smoke-test on device *before* submitting. I proposed inverting it
and Xian agreed: **archive and upload first, then install the actual TestFlight
build and smoke-test that, before enabling it for Dan.** Reasons: running from
Xcode installs a *development*-signed build over the existing TestFlight app,
and a signing-identity change can force a delete-and-reinstall — a data-loss
path we don't need to walk. Testing the TestFlight artifact also exercises the
exact thing testers receive rather than a debug proxy. Coral's actual intent —
nobody outside gets an unverified build — is preserved, and arguably better
served.
