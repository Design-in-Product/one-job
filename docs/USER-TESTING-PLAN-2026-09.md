# User testing plan — two tracks, independent dependency chains

**Status:** living plan, tracked with checkboxes as we work through it.
**Supersedes:** `USER-TESTING-PLAN-SUMMARY-2026-09.md` (2026-09-23),
which was a snapshot of what existing docs said — this is what we
actually decided, working from that snapshot, in conversation the same
day.

**The reframe that produced this structure:** the two testing tracks
were originally described as sequential (ten agentic, then forty
ordinary) with no written reason for that order. Looking at what each
track actually depends on, they turn out to share almost no critical
path — Track A is blocked on its own unproven mechanism, Track B is
blocked on nobody having built its recruiting plan yet. Those are
different kinds of unfinished, and neither is downstream of the other.
**They should run in parallel.**

---

## Track A — Agentic (Pilot, cap 10)

**Goal:** find out whether the agentic thesis holds — does an agent
handing you a card, and you working from a dealt deck, actually make
sense as an interaction model, or is it a solution in search of a
problem.

### Dependency chain

1. [ ] **Iterate the card-exchange prototype** (the rollup ↔ fleet-probe
   deck Xian and Coral have been using) until it's no longer raw.
   **This is the real blocker** — Xian: it's the reason nobody's been
   signed up yet. Next conversation.
2. [ ] Define success criteria specific to this track — not the generic
   activation/retention numbers, but what would tell us the agentic
   idea itself is working.
3. [ ] Resolve open track-fit questions (below) before recruiting into
   this specifically.
4. [ ] Recruit for real: **Rich Frankel** (friend, interested, probably
   the easiest second tester), **Sam Spieth** (friend's child, tentative
   — noncommittal, not reliable).

## Track B — Regular (Cohort, cap 40)

**Goal:** find out whether the core one-card-at-a-time loop retains
ordinary people who have no agent workflow at all.

### Dependency chain

1. [ ] Define success criteria. Activation (5 cards + 2 active days) and
   retention (4 active days in days 22–28) already exist as numbers —
   refine them to account for **full-deck cycling**: looping the whole
   deck to see what's there isn't avoidance of any one card, and the
   current per-card deferral metric can't tell it apart from N
   individual avoidant defers. (Xian, 2026-09-23 — a third failure mode
   distinct from the avoidance/recurrence split Week 1's question
   already covers.)
2. [ ] **Build an actual recruiting plan.** This doesn't exist yet, and
   unlike Track A it isn't blocked on anything technical — it's just
   undone.
3. [ ] Resolve open track-fit questions (below).
4. [ ] Write the plain-framing trial doc (Themis's agent-framed draft
   belongs to Track A; the plainer revision for this track hasn't been
   written).
5. [ ] Recruit: **Steve Portigal** (friend, UX research background,
   willing to help — target-user fit still unclear).
